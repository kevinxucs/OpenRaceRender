# RGB channels and stereo layouts (F35)

Each visual display has **RGB color channels** in its inspector. Red, green and blue independently control which destination components it can change. A disabled channel retains the picture underneath, including when the display has transparency or soft edges. Selecting only red is therefore different from painting a red-tinted opaque rectangle. All channels off draws nothing. Source picture controls remain independent.

Masks apply to cameras, images, text, shapes and telemetry widgets in the shared preview/snapshot/video renderer. Normal RGB draws retain their existing rendering path. Additional masked layers preserve destination bytes around ordinary alpha compositing, so they require a surface copy and CPU pass; stereo performance depends on frame size and camera decoding. No real-time stereo performance guarantee is made.

Masks persist in `.orrp` and reusable `.orrt` templates. Timeline events can override, clear or inherit the mask, with normal Undo. Existing native OpenRaceRender imports recover previously ignored mask bits once from their saved original display records. Subsequent edits are retained. Native RRP/RRT/RRO base masks use verified common-record RGB bits. RRP timeline mask changes use a separately verified event flag/field. Native probes also corrected base transparency/mirroring and timeline source/aspect/style/mirroring fields. Older native imports repair untouched base transparency/mirroring once; edited timelines remain intact with a warning to reimport the original RRP if needed.

**Display → Stereo camera layout…** chooses two independent video streams, eye order and an optional horizontal convergence shift. Presets include red/cyan, green/magenta, amber/blue, parallel side by side and cross-eye side by side. The pair is inserted above existing ordinary cameras and below overlays; review order when using camera groups. Source synchronization/trim, existing objects, export marks and output settings are retained. The right-eye display is muted to avoid doubled sound. The entire addition is one Undo step.

Use **Timeline → Synchronize cameras side by side…** to align the recordings, then check motion, eye order and convergence. The workflow requires footage from two physical viewpoints; it does not synthesize depth from one camera. Anaglyphs use simple RGB separation, without calibrated color matrices or display-specific crosstalk compensation. Stereo spherical metadata is outside this feature.

Validation uses original synthetic cameras and pixels: disabled-channel/alpha checks on BGRA and RGBA canvases, widget masks, timeline clear/inherit, legacy base-mask roundtrips, old-native migration, portable templates and stereo layout/Undo. `scripts/validate-color-channels.py` checks independent source-channel arithmetic, legacy reopening, encoded video and masked widget preservation. Native RaceRender's anaglyph template independently confirms red=1 and cyan=6 in common byte288. Locally supplied native templates and native comparison artifacts remain ignored.

Reference: mirrored [RaceRender display color-channel guide](https://racerender.com/RR3/docs/DispObjEdit.html).

Native verification used an original two-camera gray test with different opacity per eye. After correcting legacy byte mappings, the native preview and OpenRaceRender snapshot have identical pixels. The native inspector independently showed the intended 50% transparency. Separate saved native events verified RGB, transparency, mirror, source, aspect and style changes. This synthetic check does not establish universal footage/widget pixel parity. Live OpenRaceRender RGB toggle values, stereo sheet defaults/addition and single-step Undo were verified; the disposable UI project was saved separately.

Verified native records: base transparency byte286, mirror287 and RGB mask288. Timeline style flag1, source flag16 at relative145, aspect flag64 at147, transparency flag128 at148, mirror flag256 at149 and RGB flag512 at150 (offsets relative to the event's 200-byte value record). Unsupported clipping flags remain reported.

A matched local 2-second 1920×1080/60 fps two-camera export took 3.60 seconds with masks and 3.39 seconds with all RGB channels enabled (about 6% added time). This short synthetic measurement isolates mask overhead; it is not a native RaceRender speed comparison or a real-session benchmark.
