# Logger formats and data sessions (F31)

Add MegaSquirt/TunerStudio **text `.msl` logs** through Add input, Finder Open With, or file drop. Both comma and tab delimiters are accepted, with an optional firmware/date preamble and units row. Time in seconds or milliseconds is normalized to seconds; unsupported time units produce an error. Standard RPM, TPS, gear, GPS latitude/longitude and supported VSS units are recognized. CLT/ECT and MAT/IAT with explicit Fahrenheit units convert to Celsius; other named channels remain available for manual assignment. Mark lines are skipped. Firmware-specific channels/units are not inferred from controller binaries or INI files. Binary MS3/MLG/FRD require conversion to text MSL in the logger software.

**GUTMA flight-logging JSON** is supported, including the format emitted by Parrot's documented `liblog2gutma` exporter. It must declare Metric units, a timezone-qualified `logging_start_dtg`, unique `flight_logging_keys`, and numeric timestamped rows. GPS, altitude, ground speed, drone velocity and battery voltage receive explicit units; other numeric channels remain available by name. Missing values remain missing. Drone velocity axes are not assigned to vehicle longitudinal/lateral G. This does not claim support for every Anafi/FreeFlight JSON dialect or encrypted `log.bin` files.

**SpeedAngle R4 v4 `.sa` text logs** are supported at the documented 10 Hz trace rate, with explicit KM/h or MILE/h speed units. GPS, speed, lean angle, paired motion readings, satellites, validity and sector/finish markers remain available. Invalid GPS fixes preserve the sample clock and motion readings while GPS/speed stay missing. Matching timer/trace crossings retain millisecond lap times; inconsistent timer crossings fall back to sample-level markers with a warning. A header's local date/time has no timezone and does not receive an invented UTC anchor.

The appendix does not define the acceleration scale or timing of the second motion reading. Both acceleration columns retain **raw sensor values**, without automatic physical-G assignment; paired readings remain separate channels. A verified conversion can be assigned manually. This is v4 support, not a claim of every SA generation. Native RRP export refuses SA input mapping until native channel compatibility is verified; `.orrp` preserves the source and settings.

**Olympus `.sns` sensor logs** with identified `$OLTIM`, `$OLCMP`, `$OLPRE`, `$OLTMP`, `$OLACC` and `$OLSNSGPSTIM` text sentences are supported. The same identified content is accepted with a `.snslog` extension; the manufacturer normally uses `SNSLOG` as the directory name and `.sns` as the file extension. Packets retain their camera timestamps, pressure (hPa), metric/imperial sensor altitude, declared C/F temperature converted to Celsius, temperature status and all three raw acceleration axes. Missing fields in a packet stay missing rather than inheriting a previous value. Supplied sentence checksums are checked. Invalid dates, duplicate/reset timestamps, duplicate sensor sentences and truncated packets fail explicitly rather than guessing their timing.

Camera compass and acceleration are named camera channels, with no automatic vehicle-heading/G assignment. Mounting, gravity and raw acceleration scale require verification before manual mapping. Camera UTC is retained as reported, with a warning when uncorrected by GPS. One consistent `$OLSNSGPSTIM` offset adjusts that anchor; changing offsets retain the sample clock but omit the UTC anchor with a warning. This support follows first-hand TG-5/TG-Tracker sentence observations and does not claim every Olympus/OM generation. Unknown sentence types warn. A same-basename GPS `.log` is merged from the same folder or a sibling `GPSLOG` directory when importing an SNS file from `SNSLOG`. Pairing requires exactly one candidate, one consistent `$OLSNSGPSTIM` correction, at least two dated GP/GN RMC records and overlapping UTC ranges. RMC dates support 2000–2099; GGA-only files cannot establish the date. Invalid/void fixes retain their timestamps and missing GPS/speed. The merged clock includes both sources’ samples; sensor values interpolate within their own bounds and GPS interpolation does not bridge long receiver outages. Time zero is the earliest combined sample: check synchronization when a companion is added to an existing project. Keep both original files and folder relationships when moving the project. Ambiguous/malformed/nonoverlapping companions warn and retain the usable standalone sensors. Importing `.log` alone remains the normal GPS-only workflow. Native RRP export refuses unverified SNS channel mapping; `.orrp` preserves it.

## Choosing a session

When a new file contains multiple recognized sessions, data configuration opens with a **Data session** picker. Choose the session, preview its channels/clock and Apply. Existing sources have the same picker under **Configure data…**. Every session begins at its first sample's time zero. Check synchronization after switching. The choice is saved in `.orrp`, isolated in Undo, and retained when duplicating a source. Reusable templates and generic data profiles do not carry file-specific selections. Camera data uses its separate physical-camera clock.

Recognized boundaries are:

- Repeated identical headers in CSV/TSV/text, or a clock restarting at/before the session's first timestamp. A small isolated out-of-order row retains the existing skip-and-warn behavior. Blank lines do not split a session. The header and units must remain consistent within an MSL file. Vendor-specific Alfano layouts have not been verified against a sample.
- Separate GPX `<trk>` elements, retaining segments and gaps within one track; separate TCX `<Activity>` elements. Track names/activity IDs appear in the picker. Recorded UTC is retained.
- FIT session messages inside one container, including summary-first and summary-last recordings, plus separate complete FIT containers concatenated in one file. Ranges use `start_time + total_elapsed_time`; the summary timestamp is not treated as the end. A boundary sample belongs to the session beginning there. Lap numbering is local to each selection. Samples outside all ranges remain in a separate **Unassigned records** selection with a warning. Empty summaries are omitted, identical ranges are deduplicated, overlapping ranges and incomplete multi-session bounds fail explicitly. A single incomplete summary retains all activity records with a warning. UTC timestamps retain the FIT epoch; device-relative clocks do not receive an invented wall-clock anchor. Missing record values stay missing.
- Separate SpeedAngle trace blocks/concatenated v4 recordings, retaining each trace’s units, local name and lap crossings.
- Separate `session.json` entries in an RCZ archive, with nested channel folders isolated per session. Each session retains its own recorded UTC clock.

The CLI supports `inspect-data FILE --session 2 --time 10` and lists available session numbers/names. Source loading caches by path, settings **and selected session**, so two runs from the same file keep distinct tables. Invalid selections fail explicitly. Legacy RRP track numbers are honored when this reader can identify that session; new selections and GUTMA sources are refused by native RRP export because compatibility is unverified.

## Formats still requiring work

GTech GTR/GTS, PZRacing PRR and Sony MOFF lack a verified decoder layout and matching fixture in this implementation. The mirrored RaceRender acquisition guide names these formats but does not specify their binary structures. Sony's public support article describes MOFF as a management file rather than documenting a decoder. These formats are detected and receive a concrete CSV/GPX conversion message instead of being added as broken videos. Olympus GPS-only NMEA `.log` files continue to work through the existing NMEA reader; identified SNS sensor companion merging is supported as described above; other layouts remain unverified. Do not interpret these diagnostics as native format support. Real files/documentation are still needed to finish these parts of F31.

## Validation and sources

Original fixtures cover MSL time/speed/temperature units, restarted clocks, unknown time-unit refusal, GUTMA null/invalid GPS and UTC, GPX track/segment distinctions, TCX activities, concatenated FIT, multi-session RCZ, source-cache separation, legacy selection, duplication, template stripping and malformed-format diagnostics. Editor tests cover automatic configuration offers, private preview/Apply, saved selection, unchanged sync/marks and Undo. `scripts/validate-logger-formats.py` compares second-session MSL widgets to independent CSV snapshots and marked full/chunk video. No private logger fixtures are committed. The internal-FIT follow-up adds 6 core tests and one editor selection/Undo test (407 total). Its original summary-first/last fixtures match Garmin SDK21.218.0 decoded values; `scripts/validate-fit-sessions.py --sdk` also checks independent CSV pixels and marked full/chunk video. Only the ignored validation environment installs Garmin’s SDK; no SDK code or vendor fixtures are bundled. Live GUI verification remains unavailable because CUA’s native pipe cannot start.
