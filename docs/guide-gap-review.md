# RaceRender guide gap review — implementation choices

Reviewed 2026-10-25 against OpenRaceRender `c0aa846` (Apex GT update).

This is a decision list, not an implementation plan. All 36 items below are **pending your selection**. No application behavior was changed for this review.

## Method and scope

Read all 44 HTML files in the supplied local `racerender.com/RR3/docs` mirror, including the how-to pages, scripting reference, troubleshooting, technical information, and edition comparison. Inspected the gauge-designer and data-input screenshots as well. The singular `HowTo-MultipleDataInput.html` is a cached 404; the plural `HowTo-MultipleDataInputs.html` contains the actual instructions.

Compared the documented behavior with the current model, editor, importers, compositor, exporter, and previous workflow validations. The findings below are source-confirmed omissions or partial implementations. This review did not repeat all reference-app workflows or run a new rendering benchmark. Earlier tests and live validations establish existing functionality; they do not prove parity for controls that have not been implemented.

The mirror includes older, Windows-specific material. Windows-only WMV/AVI output, edition activation, licensing limits, and obsolete operating-system requirements are not macOS feature gaps. Network services described by the guide, particularly direct YouTube upload, would require separate investigation of their current APIs before implementation.

**Status:** Missing = no usable equivalent exposed; Partial = a useful equivalent exists, but the specified controls or behavior are absent. Effort is a rough engineering scope, not a time estimate: S = contained, M = several model/UI/render changes, L = substantial compatibility or pipeline work. IDs remain stable so you can select individual items.

## Suggested first choices

For your existing-RRP and custom-template workflows, the strongest starting set is **F01, F03, F04, F05, F07, F11, F25, and F36**. F10 is useful when you start making timed layout/camera changes. F17 matters when another logger needs manual field mapping. These are recommendations only; none is approved for implementation yet.

## Things deliberately not counted as missing

- Start/end output markers, signed brightness/contrast/saturation/sharpness, hue, RCZ import, recorded gear/temperature channels, peak speed/turn G, frame sync nudges, Finder opening, and the Apex GT instruments are already implemented.
- Multi-camera/PiP/split-screen, multiple telemetry sources, manual synchronization, timed source switches/titles, trimming/rate/delay, native joins, lap export, basic gauge customization, style picking, and native template/style saving already exist. The rows above describe their remaining scope rather than calling them absent.
- Basic arithmetic with a constant is already possible through `source × multiplier + offset`: subtraction is a negative offset; division is a reciprocal multiplier. The guide does not establish an arbitrary expression/derived-channel language, so that was not promoted to a required gap.
- Relative project paths and missing-file relinking already implement the guide's project-transfer instructions. The guide does **not** document an automatic “collect all media” project packager; that would be an optional enhancement, not a demonstrated parity omission.
- The guide does not establish input looping, keyframe interpolation/fades, a render queue, or manual lap-time overrides. Those should not be mixed into this evidence-based missing-feature list merely because another editor has them.
- Selecting smaller render dimensions and frame rates already works. Matching RaceRender's measured rendering quality or speed requires output comparisons; a guide review cannot certify it.

## Decision format

Select IDs to **implement**, IDs to **defer**, and IDs to **ignore**. Individual subfeatures can be selected, for example “F05: needle geometry and dual needles only” or “F31: MegaSquirt only.” No selection has been inferred from a recommendation in this document.
